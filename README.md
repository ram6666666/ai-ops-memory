# AI Ops Memory

Durable operational-learning and reusable-capability repository for recurring AI/work environments.

## Purpose

Reduce repeated high-capability model reasoning on solved operational problems. Accumulate environment-specific engineering knowledge across ChatGPT, Work, Claude, Codex, Google Drive, GitHub, local research tooling, LaTeX/PDF, Python/numerical workflows, literature handling, file conversion, and other recurring environments.

Target behavior: an experienced engineer returning to a familiar workstation—retrieve the established operation card or capability, confirm only what may have changed, execute with minimal model supervision, and spend reasoning on genuinely semantic or novel work.

## Two learning lanes

1. **PROACTIVE_LIBRARY** — proactively identify common mature operations and encode the shortest reliable native tool/API/library/capability route before repeated work forces rediscovery.
2. **WORK_DERIVED_LEARNING** — learn from real executions with the user: successful routes, failures, provider quirks, cost patterns, cross-model differences, and solved recovery paths.

Both lanes promote into the same stable operational knowledge only after evidence supports reuse.

## Maturity

`OBSERVED -> REPEATED -> STABLE_PLAYBOOK -> WRAPPER_CANDIDATE -> VERIFIED_CAPABILITY`

Use `DEPRECATED` when a tool, schema, environment, or route becomes stale.

## Structure

- `state/` — compact repository state and promotion rules.
- `proactive/` — proactively curated mature-operation inventory.
- `learning/` — work-derived experience and learning rules.
- `environments/` — runtime/provider profiles and cross-model capability differences.
- `operations/` — reusable operation cards and shortest verified routes.
- `capabilities/` — capability catalog, contracts, maturity and implementation status.
- `failures/` — error signatures, discriminating probes, root causes and repairs.
- `telemetry/` — reliability/efficiency evidence including cognitive-waste proxies.

## Authority boundary

This repository is authoritative for operational knowledge and capability status only. It does not create scientific truth, project scope, task authorization, permissions, acceptance decisions, or user preferences by observation alone. Current provider/tool schemas override stale stored call shapes.

Never store secrets, credentials, transient authorization codes, private access tokens, or sensitive authentication material here.

## Runtime relationship

Google Drive keeps a searchable runtime manual for narrow retrieval during active work. This repository is the durable versioned knowledge/capability layer; Drive is the fast runtime mirror, not a competing canonical implementation store.
